### 1. プレースホルダー（完了）

ログイン後にサイドバーから束一覧を開き、デモの束のページへ移れるところまで作った。

| issue | PR | 内容 |
| --- | --- | --- |
| #1 | #3 | 束一覧ページ `/anki`。`Anki` モジュールの組み込み、`AuthMiddleware`、サイドバーのリンク |
| #2 | #4 | 束のページ `/anki/decks/demo`。「準備中」の表示と、束一覧に戻るリンク |

- URL は `{deck}` で受けずに固定の `/decks/demo` にした。段取り3で本物の束 ID に替えるときに消す
- サイドバーの選択表示はパスの完全一致で判定しているので、束のページでは「暗記カード」が選択中にならない。今は困らないのでそのままにしている

### 2. 固定10枚の学習画面

コードに書いた10枚のカードで学習する画面を、学習のページ `/anki/decks/demo/study` に作る。10枚を最後まで学習し、まとめまで表示できたら完了。

```
/anki/decks/demo        カード一覧のプレースホルダーのまま。「学習する」リンクを置く
   ↓
/anki/decks/demo/study  1ページの中で表示を切り替える
   学習設定（枚数と開始ボタンだけ）→ 学習 → まとめ（「カード一覧へ」「もう一度」）
```

| 作る | まだ作らない |
| --- | --- |
| タップと Space での表裏の切り替え | DB、API、IndexedDB |
| 前へ・次へ、進捗の表示（例: 3 / 10） | 出題設定の選択（表→裏・登録順で固定） |
| 暗記済み・苦手のフラグ（メモリ上だけ） | カードの編集、タグ |
| まとめの画面、キーボード操作 | マークダウンの描画（平文で表示） |

- フラグや進捗はリロードで消えてよい。保存の仕組みは段取り3で入れるので、`localStorage` などで仮の保存処理は作らない
- 固定のカードも、要件のデータモデルと同じ形にする: `{ uuid, front_md, back_md, front_size, back_size, f2b_status, b2f_status, tags }`
- 学習画面は固定の配列を直接読まず、`store.js` の関数を通して受け取る。段取り3では、その中身を差し替えるだけにする
- esbuild はこの段取りで入れる。「Alpine 本体より先に JS を読み込む」という要件も、ここで確かめる
- 10枚の中に、1行だけのカードと画面に収まらない長文のカードを混ぜる。縦中央の配置とスクロールを確かめるため

### 3. データの保存と同期

カードの取り出し元を、固定のデータからサーバー（DB）に替える。

- 学習設定を開いたときに全カードの軽い情報を取得し（`meta`）、学習を始めるときに出題するカードの本文を取得する（`cards/bodies`）
- 学習中の操作は、送信待ちの列（IndexedDB）に積んで `/anki/sync` で送る

学習画面がほぼそのままで動くこと、学習を始めたあとにオフラインで操作しても、再接続後に同期されることを確かめる。
